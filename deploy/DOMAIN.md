# Подключение домена и HTTPS к тренажёру мнемотехники

Ваш сайт уже работает по IP-адресу 161.104.16.174.
Эта инструкция поможет сделать его доступным по красивому домену
(например, mnemonics.ru) с защищённым соединением https.

---

## Шаг 1. Купите домен (если ещё нет)

Купить можно прямо на рег.ру: https://www.reg.ru/domain/new/
Выберите имя, оплатите — он появится в личном кабинете через несколько минут.

---

## Шаг 2. Направьте домен на ваш сервер (A-запись DNS)

1. Войдите в личный кабинет рег.ру → раздел **«Домены»**
2. Нажмите на ваш домен → вкладка **«DNS-серверы и управление зоной»**
3. Нажмите **«Добавить запись»**
4. Заполните:
   - **Тип записи:** A
   - **Хост/Поддомен:** `@`  *(означает «сам домен», например mnemonics.ru)*
   - **IP-адрес:** `161.104.16.174`
   - **TTL:** оставьте по умолчанию (3600)
5. Сохраните запись
6. Добавьте ещё одну запись для www:
   - **Тип:** A
   - **Хост:** `www`
   - **IP-адрес:** `161.104.16.174`

> DNS обновляется в течение 30 минут — 2 часов. Пока ждёте, выполните Шаги 3–4.
> Проверить готовность можно здесь: https://www.whatsmydns.net — введите домен и тип A.

---

## Шаг 3. Войдите на сервер по SSH

С вашего компьютера откройте терминал (на Mac: Терминал, на Windows: PowerShell):

```bash
ssh root@161.104.16.174
```

Введите пароль (тот, что есть или новый, если меняли).

---

## Шаг 4. Впишите домен в настройки nginx

> Замените `ВАШ_ДОМЕН.ru` на ваш реальный домен в командах ниже.

```bash
nano /etc/nginx/sites-available/mnemonics
```

Найдите строку:
```
server_name 161.104.16.174 _;
```

Замените её на:
```
server_name ВАШ_ДОМЕН.ru www.ВАШ_ДОМЕН.ru;
```

Сохраните: `Ctrl+O` → `Enter` → `Ctrl+X`

Проверьте и перезапустите nginx:
```bash
nginx -t
systemctl restart nginx
```

---

## Шаг 5. Убедитесь, что домен уже ведёт на сервер

Откройте в браузере http://ВАШ_ДОМЕН.ru (без https).
Должен открыться тренажёр. Если видите пустую страницу или ошибку — DNS ещё не обновился, подождите немного и попробуйте снова.

> Пока сайт не открывается по домену — к Шагу 6 не переходите.
> Certbot должен видеть домен, иначе выдаст ошибку.

---

## Шаг 6. Установите сертификат HTTPS бесплатно

Установите certbot (если ещё не стоит):
```bash
apt install -y certbot python3-certbot-nginx
```

Запустите получение сертификата:
```bash
certbot --nginx -d ВАШ_ДОМЕН.ru -d www.ВАШ_ДОМЕН.ru
```

Certbot задаст несколько вопросов:
- **Enter email address** — введите вашу почту (для уведомлений об истечении)
- **Agree to the ACME...** — введите `Y`
- **Share your email with EFF** — на своё усмотрение, можно `N`

Certbot сам обновит nginx и включит https. В конце вы увидите:
```
Successfully received certificate.
...
Congratulations! You have successfully enabled HTTPS
```

---

## Шаг 7. Проверьте результат

Откройте браузер и перейдите на https://ВАШ_ДОМЕН.ru

Должен открыться тренажёр с зелёным замком в адресной строке.
Обращение по http:// должно автоматически перенаправлять на https://.

Проверьте также API:
```bash
curl https://ВАШ_ДОМЕН.ru/api/healthz
```
Должно вернуть: `{"status":"ok"}`

---

## Продление сертификата (автоматически)

Certbot сам продлевает сертификаты. Проверить, что автопродление настроено:
```bash
systemctl status certbot.timer
```
Если статус `active (waiting)` — всё в порядке. Сертификат действует 90 дней
и обновляется автоматически.

---

## Если что-то не работает

**«Connection refused» или «Site not found»**
→ DNS ещё не обновился. Проверьте на https://www.whatsmydns.net

**Certbot ошибка «Connection refused» или «No valid IP»**
→ Nginx не запущен или A-запись ещё не подтянулась. Проверьте:
```bash
systemctl status nginx
```

**Сайт открывается, но замок красный**
→ Попробуйте снова через несколько минут — браузер мог закэшировать.

**Certbot ошибка «too many certificates»**
→ Лимит 5 попыток в неделю. Подождите 7 дней или уберите `-d www.` из команды.
